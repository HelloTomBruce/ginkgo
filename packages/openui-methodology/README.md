# @openui-analytics/methodology

OpenUI Analytics 的方法论资产包：将通用数据分析思维抽象为**纯数据方法卡（MethodCard）**，配套提供注册表合并、数据校验与受字节预算严格约束的 Prompt 渲染纯函数。

## 包定位

- **纯资产与无副作用模型**：作为 monorepo 中最纯粹的资产包，零运行时第三方依赖，仅由强类型定义、纯数据卡片与纯函数组成。包内不反向导入任何前端组件、服务端运行时或具体模型编排逻辑。
- **分析业务思维沉淀**：将业务分析中常见的通用分析套路（如趋势分析、归因分析、漏斗转化、RFM 分层等）标准化，使上层模型编排对具体卡片数量和业务领域零侵入感知。
- **与兄弟包的依赖关系**：
  - 为 `@openui-analytics/llm` 提供方法索引（注入规划阶段 Prompt）与单卡执行指导（注入执行阶段 Prompt）；
  - 方法卡中声明的推荐组件配对（`chartPairing`）与展示组件库 `@openui-analytics/components` 的组件名保持一一对应；
  - 驱动应用前端侧栏的「快捷推荐提问」列表生成与方法论目录浏览。

## 核心架构

方法论包采用**卡片纯数据契约 + 注册表保序合并 + 服务端字节预算渲染**的三层设计：

```
+-------------------------------------------------------------------------------+
|                       MethodCard 纯数据契约 (类型定义)                          |
|  - id / 命名规范  - 适用场景 (when)  - 预设提问 (presetQuery)                 |
|  - 步骤拆解 (steps) - 组件配对 (chartPairing) - 执行指导 (executeGuidance)   |
+---------------------------------------+---------------------------------------+
                                        |
    +-----------------------------------+-----------------------------------+
    |                                                                       |
    v                                                                       v
+-------------------------------+                       +-------------------------------+
|    内置方法卡库 (cards.ts)     |                       |    动态扩展卡 (外部 JSON 文件)  |
|  - 10 张经典业务分析方法卡    |                       |  - 用户自定义业务卡片          |
|  - 领域中立表达               |                       |  - 同 ID 覆盖定制内置行为     |
+---------------+---------------+                       +---------------+---------------+
                |                                                       |
                +---------------------------+---------------------------+
                                            |
                                            v
+-------------------------------------------------------------------------------+
|                      createMethodLibrary (合并与校验注册表)                   |
|  - 集合保序合并 (内置保序 + 自定义同名覆盖与追加)                             |
|  - 双重校验: 字段完整性初筛 + 调用方动态注入的组件名白名单校验                |
|  - 容错过滤: 无效卡自动记录 skipped 并跳过，绝不阻塞应用启动                   |
+---------------------------------------+---------------------------------------+
                                        |
                                        v
+-------------------------------------------------------------------------------+
|                        受限字节预算 Prompt 渲染器                             |
|  - renderMethodIndex: 紧凑单行方法索引 (严格限制 <= 1024 字节)               |
|  - renderCardDetail: 结构化单卡执行指导 (步骤保序截断, 严格限制 <= 600 字节)  |
+-------------------------------------------------------------------------------+
```

### 1. 纯数据卡片契约（MethodCard）
卡片作为不可变数据对象，规范了分析方法的标识、名称、适用信号（`when`）、推荐提问语句（`presetQuery`）、推荐使用的可视化组件名集合（`chartPairing`）以及详细的操作步骤和指导。

### 2. 具备容错能力的合并注册表（Registry）
支持将静态内置卡集与运行时从外部读取的自定义卡集进行合并。采用“同名覆盖、新增追加”的合并策略；对不合规的卡片采用容错剔除策略并记录跳过原因，保证即使存在格式损坏的卡片也不影响系统初始化。

### 3. 基于严格字节预算的 Prompt 渲染器
为了防止方法论内容过度侵占大模型的上下文 Token 空间，所有文本渲染纯函数均以 UTF-8 字节数为硬门禁进行保序截断与优雅降级。

## 核心功能

- **内置 10 大通用分析思维方法卡**：
  - **趋势与同比环比（`trend`）**：分析指标随时间推移的变化形态与周期对比；
  - **构成与帕累托（`pareto`）**：分析头部关键少数的贡献占比（二八原则）；
  - **漏斗转化（`funnel`）**：多阶段流程中各节点的流失率与留存转化；
  - **RFM 分层（`rfm`）**：基于最近交互、频次与数值维度的客群价值分层；
  - **同期群留存（`cohort`）**：不同入流批次的行为留存与流失曲线比对；
  - **异常检测（`anomaly`）**：识别偏离基线或正常区间的离群异动；
  - **维度拆解归因（`attribution`）**：排查导致指标升降的核心维度与主要驱动力；
  - **目标达成与差距（`goal-gap`）**：对比实际进度与目标/预算/SLA 的完成差距；
  - **排名与头尾分析（`ranking`）**：头部优胜者与尾部落后者的对比分析；
  - **数值分布与离群（`distribution`）**：统计分布偏态、区间分桶与极端值影响。
- **卡片校验与合法性过滤**：
  - 检查卡片 ID 格式（小写字母开头、仅限中划线与数字组合）；
  - 步骤数充足性校验（分析步骤不得少于 2 步）；
  - 动态组件映射校验：根据上层注入的可用组件名集合，验证卡片声明的推荐组件是否真实存在。
- **受控 Prompt 渲染机制**：
  - **方法索引文本生成**：将多张卡片压缩为紧凑的单行列表（`- id: name — when`），严格限制在 1024 字节以内，超限时截断并提示省略；
  - **单卡详情渲染**：结构化输出前置条件、推荐图表配对、编号步骤与具体操作指导，严格限制在 600 字节以内，超限时自后向前精简步骤。

## 业务逻辑与流转机制

### 1. 双重角色驱动模式
方法卡中的 `presetQuery`（预设提问）字段具有双重驱动职责：
- **驱动侧栏快捷推荐**：前端挂载后读取方法论库，凡包含 `presetQuery` 的方法卡会自动展示在聊天侧边栏的「推荐场景」列表中，点击即可将领域中立的提问模板填入输入框；
- **驱动模型意图对齐**：为大模型理解该方法卡能解决什么样的自然语言问题提供标准示范。

### 2. 一张方法卡的端到端流转时序
1. **定义与聚合**：内置方法卡加载，同时扫描外部自定义 JSON 目录，合并为统一的方法论知识库；
2. **规划阶段（Plan）**：大模型生成方案时，编排层通过 `renderMethodIndex` 将全量方法索引注入系统提示词，引导模型识别用户意图并选择合适的方法卡 ID；
3. **执行阶段（Execute）**：在用户确认执行方案后，编排层在上一步生成的规划卡片（`PlanReviewCard`）中利用词边界与中文卡名精准匹配命中的方法卡（最多选出 2 张），随后调用 `renderCardDetail` 将单卡详细操作指引注入当前执行轮次的 Prompt；
4. **组件物化**：模型遵循方法卡推荐的 `chartPairing` 与执行指南，选择对应的展示组件（如 `SpecChart`、`FunnelChart` 或对应布局模板）生成展示代码。

### 3. 字节预算硬防护原则
由于模型上下文窗口有限且计费敏感，本包坚决拒绝将完整的方法论全文全量注入 Prompt。索引渲染限制在 1024 字节，超限按原有顺序保留前面的核心卡片；单卡详情限制在 600 字节，超限优先裁掉尾部次要步骤，若仍超出再裁剪执行指南文本，始终守住预算上限。

## 扩展指南

- **新增内置方法卡**：
  在内置卡片列表中添加符合契约的对象，提供严谨的场景描述、至少 2 个逻辑步骤、有效的组件配对名及引导说明。新增后卡片将自动同步至推荐列表与提示词索引中，无需修改任何编排代码。
- **免代码添加自定义业务方法卡**：
  在应用运行时数据目录下的 `data/methodology/` 路径中放入自定义 JSON 文件（支持单卡对象或卡片数组）。应用在启动时将自动读取并合并；若自定义卡与内置卡 ID 相同，将直接**覆盖**内置卡内容，实现特定业务场景下的方法定制。
