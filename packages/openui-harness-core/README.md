# @openui-analytics/harness-core

企业级通用 LLM Harness 执行与治理底座：领域无关、零业务硬编码、中间件驱动，具备输出自愈、状态图编排、多租户成本控制与分布式流式任务治理能力。

## 包定位

- **底层执行与治理引擎**：作为 monorepo 中通用 AI Agent 与 LLM 调用的核心运行时底座，封装所有与具体分析业务无关的基础设施能力（通信弹性、中间件管线、上下文与状态机编排、成本核算、可观测性等）。
- **零业务假设**：包内不包含任何特定数据分析、特定图表或前端 DSL 的代码，可作为通用库为上层编排层（如 `@openui-analytics/llm`）或其他 AI 服务提供基础支撑。
- **依赖生态**：基于 Vercel AI SDK（`ai`）、`@modelcontextprotocol/sdk`、`zod` 构建，提供针对 Redis、分布式文件及内存的多种存储适配器。

---

## 核心架构

Harness 采用**分层松耦合、门面装配、中间件穿透与状态机编排**的架构设计：

```
+-------------------------------------------------------------------------------+
|                             HarnessCore (统一门面)                             |
|  - 分层配置解析 (环境变量/动态覆盖)  - 会话流中继 (StreamHub)   - 统一 MCP 管理器      |
|  - 成本核算台账 (CostLedger)       - 任务快照存储 (TaskStore)  - 全局遥测入口        |
+---------------------------------------+---------------------------------------+
                                        |
    +-----------------------------------+-----------------------------------+
    |                                                                       |
    v                                                                       v
+-------------------------------+                       +-------------------------------+
|   洋葱中间件管线 (Pipeline)     |                       |    状态图编排 (StateGraph)     |
| - 凭证检查 (CredentialGuard)  |                       | - 节点动作 (NodeAction)       |
| - 并发限流 (ConcurrencyGate)  |                       | - 条件分支路由 (Router)        |
| - 租户配额 (TenantQuota)      |                       | - 检查点快照 (Checkpointer)   |
| - 输出自愈 (AutoHealing)      |                       | - 人工介入断点 (Breakpoint)    |
+---------------+---------------+                       +---------------+---------------+
                |                                                       |
                +---------------------------+---------------------------+
                                            |
                                            v
+-------------------------------------------------------------------------------+
|                           运行时弹性与基础设施适配层                           |
|  - Provider 抽象与弹性重试 (ResilientFetch: 指数退避、状态码分类、熔断保护)       |
|  - FinOps 成本治理 (模型定价矩阵、滑窗计费、多后端台账: Memory / File / Redis)  |
|  - StreamHub 任务中继 (独立后台 Reader、多端广播重放、进程重启容错)             |
|  - 可观测性遥测 (Telemetry: Console / Prometheus Metrics / OpenTelemetry)    |
|  - 推理思考流转换 (Reasoning: reasoning_content 统一归一化为 <think> 标签)     |
+-------------------------------------------------------------------------------+
```

### 1. 统一管理门面（HarnessCore）
通过聚合配置解析、存储适配器装配、MCP 客户端管理、流中继中心与成本账本，对外提供简洁的单例初始化入口，支持在运行时通过配置补丁热更新参数。

### 2. 洋葱模型执行管线（Pipeline & Middlewares）
提供类似 Koa 的中间件执行链路，对每个 LLM 请求依次执行前置校验、并发控制、租户限额、上下文增强及后置自愈重试，确保执行流的安全受控。

### 3. 状态图编排与人机协同（StateGraph & Human-in-the-Loop）
提供有向状态图执行能力。每个节点接收全局状态并返回状态更新补丁；支持条件边动态路由；内置基于 Checkpointer 的快照机制，支持在关键节点配置断点（Breakpoint）暂停执行，等待人工审批或外部输入后无缝恢复执行。

### 4. 存储与多租户解耦
针对流式任务快照与成本账本，抽象出统一接口并提供三套实现：
- **内存实现（InMemory）**：适用于轻量单机或单元测试；
- **文件持久化（File / Ndjson）**：适用于单机部署下的持久化与重启容错；
- **分布式集群（Redis）**：适用于多实例横向扩展、分布式并发锁与全局配额控制。

## 核心功能

- **洋葱中间件套件**：
  - **凭证守卫（CredentialGuard）**：拦截未提供有效 API Key 的非法请求；
  - **并发门禁（ConcurrencyGate）**：限制单租户或全局最大并行 LLM 请求数，超限排队或拒绝；
  - **租户配额管理（TenantQuota）**：按时间滑窗限制租户请求次数与 Token 消耗上限；
  - **自愈中间件（AutoHealing）**：捕获下游输出校验失败事件，自动将错误提示注入上下文并触发自愈重试。
- **模型提供商与通信弹性（Providers & Resilience）**：
  - 支持 OpenAI、Anthropic 及各类兼容推理模型协议；
  - **弹性 Fetch 包装**：精准区分可重试错误（网络波动、429 限流、5xx 瞬时故障）与不可重试错误（401 鉴权失败、400 参数非法），内置带抖动的指数退避重试；
  - 维护模型上下文窗口字典，提供安全阈值钳制与模型能力探测。
- **企业级 FinOps 成本账本**：
  - 内置主流大模型每百万 Token 输入/输出/缓存读取的计费价格表；
  - 实时计算每次调用成本并沉淀至结构化台账，支持按租户、模型、时间窗口进行成本统计与预算控制。
- **高可用流式任务中继（SessionStreamHub）**：
  - 解耦上游 LLM 生成生命周期与下游客户端连接，服务端由独立 Reader 消费上游响应并写入分块缓冲区；
  - 支持多端订阅重放、断线重连恢复以及显式即刻取消；
  - 终态缓冲保留窗口支持任务结束后的回溯查看。
- **统一可观测性与追踪（Telemetry）**：
  - 统一事件模型记录请求全生命周期事件（开始、Token 生成、工具调用、中断、完成、失败）；
  - 支持接入 Console 日志、Prometheus 统计指标及 OpenTelemetry 分布式链路追踪。
- **标准 MCP 客户端接入与适配**：
  - 管理跨 Stdio / SSE / HTTP 的多 MCP Server 连接池；
  - 自动将 MCP 工具规范转换为 Vercel AI SDK 兼容的 CoreTool 实例。

## 业务逻辑与流转机制

### 1. 中间件洋葱流转机制
请求进入管线后，按序穿过各个中间件的前置阶段（如校验鉴权、扣减并发计数），随后进入核心模型调用或工作流执行。执行完成后，自内向外穿过各中间件的后置阶段（如统计耗时、回写 Token 用量、释放并发锁）。任一前置中间件若拦截（如配额耗尽），直接生成响应短路返回。

### 2. 状态图执行与断点挂起恢复
1. **执行循环**：从 `START` 节点出发，根据边配置或条件路由函数依次跳转至后续节点执行动作；
2. **状态合并**：每次节点执行返回局部状态切片，通过浅合并或自定义 Reducer 更新全局状态并持久化检查点快照；
3. **断点中断（Human-in-the-Loop）**：执行到声明了断点的节点前，图引擎持久化当前任务状态并挂起返回，等待外部人工确认；
4. **状态恢复**：接收外部恢复指令与人工输入后，从保存的快照处无缝继续后续分支执行。

### 3. 自愈守卫（AutoHealing）流转
当模型生成的输出需要满足强结构约束（如 JSON Schema 或特定 DSL）时，自愈守卫介入：
- 若验证器校验通过，直接交付下游；
- 若验证失败，守卫将格式化后的验证报错信息转化为修正式系统提示，在剩余最大重试次数内重新唤醒模型生成，直到通过验证或达到重试上限降级。

### 4. 推理流字段标准化
针对深度思考型模型（如 DeepSeek R1、Qwen 推理版等）在各网关返回非标准字段（`reasoning_content`、`thought`、`reasoning`）的现状，内置流式转换器在传输层拦截并将其统一映射为标准的 `<think>` 标签，确保下游解析与前端打字机无缝兼容。

## 扩展指南

- **添加自定义中间件**：
  实现 `HarnessMiddleware` 接口，在 `next()` 调用前后分别处理拦截、上下文注入或结果修饰，随后挂载至 `HarnessPipeline`。
- **自定义状态图编排**：
  利用 `StateGraph<TState>` 定义状态模型、添加动作节点与条件边，调用 `.compile({ checkpointer })` 编译成可执行工作流实例。
- **接入新的存储或成本账本后端**：
  实现 `TaskStore`（流任务状态存储）或 `CostLedger`（用量账本）接口，并在门面初始化时注入。
- **扩展遥测导出器**：
  实现 `TelemetrySink` 接口的 `emit(event)` 方法，接入企业自建日志或监控分析平台。
