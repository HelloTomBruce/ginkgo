# @openui-analytics/components

OpenUI 规范展示组件库：聚合展示组件、分析布局模板、图表注册表、筛选联动总线与容错基础设施，经 `createLibrary` 导出为 `analyticsLibrary`，供应用端及大模型流式渲染器消费。

## 包定位

- **纯展示与渲染层**：本包是「看板长什么样」的唯一渲染实现，涵盖展示组件、布局模板与容错兜底；不承担数据源取数与 SQL 执行职责（由数据层及服务端物化链路完成）。
- **解耦设计**：组件不直接依赖应用层全局状态（如 Toast、路由、鉴权 Session 等）。当需要触发应用层行为时，统一通过 action 流（如 `@openuidev/react-lang` 的 `useTriggerAction`）向上派发，保持高内聚与可测试性。
- **与兄弟包的依赖关系**：
  - 依赖 `@openui-analytics/chart-spec`：引用 `ChartSpec`（维度/指标/图表类型）与 `DashboardSpec` 2.0 状态树规范；
  - 支撑 `@openui-analytics/llm`：本包组件规范与布局能力对应 LLM 侧的组件定义（`serverLibrary`）与 Prompt 知识库；
  - 依赖 `@openuidev/react-lang`：提供 `defineComponent`、`createLibrary`、`Renderer` 等解析与渲染底座。

## 核心架构

展示组件体系采用**分层定义 + 故障隔离 + 声明式渲染**的三层设计：

```
+------------------------------------------------------------------------+
|                          analyticsLibrary                              |
|          (统一注册表: 聚合全部布局模板、指标、图表、表格、洞察等组件)            |
+------------------------------------+-----------------------------------+
                                     |
    +--------------------------------+--------------------------------+
    |                                                                 |
    v                                                                 v
+-----------------------+                                   +-----------------------+
|  组件定义 (OpenUI Def) |                                   | 声明式看板 (Spec)      |
|  - defineComponent    |                                   | - DashboardSpecRenderer|
|  - 宽松 Props Schema   |                                   | - 栅格系统 (Grid/Rows) |
|  - 运行时类型收敛与清洗 |                                   | - QueryBinding 绑定   |
+-----------+-----------+                                   +-----------+-----------+
            |                                                           |
            v                                                           v
+-----------------------+                                   +-----------------------+
|    纯 React 组件       |                                   |  SpecChart / Registry |
|  - 独立可用 (无 DSL)   |                                   |  - 换图不换数据       |
|  - 语义 Token 样式驱动|                                   |  - Recharts 图表分发  |
+-----------------------+                                   +-----------------------+
```

### 1. 三层组件构造模式
每个展示组件均由两个同源实体构成：
- **纯 React 组件**：可脱离 OpenUI DSL 直接作为普通 UI 组件在前端引入并使用；
- **OpenUI 定义（`defineComponent`）**：定义组件元数据、描述文本、对 LLM 容错的 Props Schema，以及负责将不可预期的模型输出安全转换为强类型 React Props 的收敛函数；
- **聚合出口**：按分类归集全部组件定义，生成用于解析 OpenUI DSL 的渲染库实例与组件目录。

### 2. 细粒度单组件故障隔离（ErrorBoundary）
每个组件定义统一由安全外层包裹。当单一组件因非法数据结构或解析异常触发错误时，就地降级为告警占位卡，绝不击穿整个看板。结合内容签名变化触发自动复位，流式输出过程中因中间半成品语法错误导致的异常，会在完整 Token 到达时自愈。

### 3. 安全插槽机制（layoutZone）
针对复合布局模板，采用安全区块解析器处理各个命名插槽（Zone）。插槽负责严格判空、安全执行子组件 AST 的物化转换，并捕获单个 Zone 的解析异常进行局部降级，防止由于局部参数缺失导致整页白屏。

### 4. 声明式看板渲染器（DashboardSpecRenderer）
针对 DashboardSpec 2.0 打造的状态树物化容器。接收声明式规范与外部数据字典，按照行与网格配置将各部件分派到对应展示组件，支持在无需全量重载的情况下通过 JSON Patch 进行增量刷新与部件微调。

## 核心功能

### 1. 分析布局模板
针对典型业务分析场景提供即开即用的高阶布局模板：
- **BI 综合报表（ReportLayout）**：页头 + 全局控制栏 + 顶部 KPI 横排网格 + 双列图表区 + 全宽明细表格 + 洞察结论区，适用于周期性业务复盘。
- **深钻归因（FocusLayout）**：核心主图区（占 2/3 宽）+ 侧边紧凑洞察栏（占 1/3 宽）+ 底部明细，针对单一指标异动的下钻排查。
- **双栏对比（ComparisonLayout）**：带对比对象标签的左右分栏面板（A/B 测试或两实体对比）+ 底部裁决结论区。
- **监控巡检（MonitoringLayout）**：系统健康状态标识（正常/警告/严重）+ 状态横幅 + 异动指标网格 + 异常明细列表 + 应急行动处置区。
- **留存队列（CohortRetentionLayout）**：留存核心指标 + 队列留存热力矩阵 + 衰减趋势曲线 + 留存归因分析。

### 2. 图表与可视化体系
- **统计图表系列**：基于 Recharts 封装，涵盖折线图、面积图、柱状图、双 Y 轴复合图（ComboChart）、漏斗图（FunnelChart）、雷达图（RadarChart）与热力图（ContributionHeatmap）。
- **语义图表契约（SpecChart）**：接收维度、指标、过滤器声明，由注册表动态路由至真实图表渲染器，支持“换图不换数据”。
- **双 Y 轴刻度对齐算法**：内置刻度优化算法，确保左轴与右轴在不同极值区间下刻度线数量保持一致，网格线严格对齐。

### 3. 指标、明细与洞察呈现
- **核心指标卡（MetricCard / GaugeProgress）**：支持环比/同比趋势呈现、目标完成度仪表盘、状态色点与紧凑栅格布局。
- **明细与排行榜（DataTable / RankingList）**：支持结构化数据表格展示、字段语义格式化、指标条形图内嵌与 CSV 安全导出。
- **结论与行动卡（InsightBox / ActionPlanCard / ActivityTimeline）**：结构化展示分析结论、后续建议、责任人分派与阶段时间线。

### 4. 交互控件与筛选总线
- **控制与筛选组件（AnalyticsFilterBar）**：提供时间范围、维度下拉单选与多选交互控件。
- **事件与行动按钮（ActionButton / ReactiveSimulator）**：支持指标参数微调与预测模拟，通过事件流与宿主环境通信。

## 业务逻辑与流转机制

### 1. 宽进严出的双层校验策略
- **流式半成品容错**：在组件库侧，由于 LLM 采用逐 Token 流式输出，中间态常伴随截断的 JSON、非标准数组或非强类型数据。因此渲染侧采用宽松 Schema 接收，并在组件内部使用收敛函数统一清洗（如安全解析字符串化数组、枚举白名单校验、数值兜底）。
- **服务端强 Schema 约束**：真正的强类型约束部署在 `@openui-analytics/llm` 端，用于指导大模型生成标准结构。此策略既保障了模型推理规范，又避免了流式渲染在接收过程中高频抛错。

### 2. 筛选联动总线（FilterBus）
- **发布-订阅模型**：通过全局或作用域总线解耦筛选栏与展示图表。`AnalyticsFilterBar` 产生交互时广播筛选变更事件；`SpecChart`、`AnalyticsChart` 及 `DataTable` 订阅该事件并在内部对当前数据进行动态过滤切片，或触发重物化流程。
- **作用域隔离（ScopeProvider）**：支持为不同看板容器划分独立作用域，防止同一页面内多块看板之间的筛选条件交叉串扰。

### 3. 设计系统与主题 Token 映射
- **零硬编码色板类**：组件禁止硬编码任何固定颜色类名（如 `bg-blue-500`），必须使用语义化 Token（如 `bg-card`、`text-foreground-subtle`、`bg-info-soft`）。
- **动态图表颜色**：图表调色板全部基于 CSS 变量引用（`var(--chart-1..6)`），由客户端根据当前系统色彩模式（亮色/暗色）自动计算并渲染至 SVG，无需 SSR 端额外转换。
- **阈值条件着色**：根据指标值与预设阈值的关系，自动匹配对应的语义色状态（成功/警告/危险/信息）。

### 4. 数据导出安全与规范
- 明细导出严格遵循 RFC 4180 标准进行 CSV 字段转义与换行包装，同时内置针对公式注入（Formula Injection）的前缀转义防护，防止生成的表格在办公软件打开时触发恶意脚本。

## 扩展指南

- **新增展示组件**：
  1. 编写独立纯 React 组件与对应的 `defineComponent` 包装；
  2. 使用安全外层包裹以确保故障隔离，Props Schema 保持容错收敛风格；
  3. 在包入口的分类注册表中登记，组件库清单与实况预览目录将自动同步；
  4. 同步更新 `@openui-analytics/llm` 服务端组件定义与 Few-Shot 示例。
- **新增图表渲染器**：
  在图表注册表中按图表类型枚举增加分支并对接组件，确保与 `@openui-analytics/chart-spec` 的图表词汇表完全闭合。
